## 三、GeeLark 设备生命周期 SOP

### 3.1 开机前准备
- 所有素材（文案、图片、视频）提前准备好并推送到 VPS 可下载地址
- 明确本次操作目标，禁止开机后再想文案
- 准备好需要执行的脚本

### 3.2 开机流程
```
1. POST /phone/start → body: {"ids":["635151138366175341"]}
2. 轮询 POST /phone/status → 等待 status=0 (running)，约 20-40 秒
```

### 3.3 ADB 连接流程
```
1. POST /adb/setStatus → body: {"ids":["635151138366175341"],"open":true}
   ⚠️ 关键：必须是 "open":true，不是 "status":1（误用会 success 但 getData 返回 "adb did not opened"）
2. 等待 3 秒
3. POST /adb/getData → body: {"ids":["635151138366175341"]}
   → 返回 data.items[0].{ip, port, pwd}
   ⚠️ 每次开机端口和密码都会轮换，旧凭证失效，必须重新获取
4. adb connect ip:port
5. adb -s ip:port shell glogin <pwd>
   ⚠️ 不 glogin 设备会拒绝后续 shell 命令
```

### 3.4 操作执行
- 搜索/浏览/采集：VPS 上 ADB 脚本完成
- 截图回传：SFTP 回传
- UI 文本解析：`adb shell uiautomator dump` 解析 XML
- 点击：`adb shell input tap x y`
- 滑动：`adb shell input swipe x1 y1 x2 y2`

### 3.5 收尾停机（省钱铁律）
```
1. adb shell am force-stop <包名>
2. adb disconnect
3. POST /adb/setStatus → body: {"ids":["635151138366175341"],"open":false}
4. POST /phone/stop → body: {"ids":["635151138366175341"]}
5. 确认 status=2（已关机）
```
⚠️ **US Reality 按分钟计费，用完立刻关机，铁律！**

## 九、常见问题与故障排除

### 9.1 ADB 连接失败
- 症状：`adb/setStatus` 返回 success 但 `adb/getData` 返回 "adb did not opened"
- 原因：使用了错误参数 `{"status":1}` 而非 `{"open":true}`
- 解决：确保 body 为 `{"ids":[...],"open":true}`

### 9.2 Shell 命令被拒绝
- 症状：`adb shell` 命令无响应或报错
- 原因：未执行 `glogin` 登录
- 解决：先执行 `adb -s ip:port shell glogin <pwd>`

### 9.3 ADB 凭证失效
- 症状：之前获取的 ip:port 连不上
- 原因：每次开机端口和密码都会轮换
- 解决：每次开机后必须重新 `adb/getData` 获取新凭证

### 9.4 社媒平台风控
- 症状：操作被限制、验证码弹出、账号异常
- 原因：操作频率过高 / IP 不一致 / 行为模式异常
- 解决：降低操作频率、检查 IP 是否一致、增加随机等待时间、暂停操作 24-48 小时

### 9.5 设备未关机
- 症状：月底发现费用异常高
- 原因：任务脚本结尾未调用停机
- 解决：**任务脚本结尾必须带停机调用**，写死在脚本最后一步
