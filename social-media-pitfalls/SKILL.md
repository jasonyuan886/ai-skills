## 坑点清单

### 坑点1：X.com 持久登录失败

**问题现象：**
- 每次操作 X.com 都需要重新登录
- 无法保持登录状态
- 操作效率极低

**根因分析：**
代理路径配置不正确，导致浏览器 profile 无法持久化 cookie/session。每次启动浏览器时都相当于一个全新的会话。

**解决方案：**
1. 使用稳定的**静态住宅代理**（IPRoyal Static Residential ISP 类型）
2. 正确配置浏览器 profile，确保 cookie 和数据持久化
3. 代理路径必须一致，不能每次操作切换不同的代理节点

**预防措施：**
- 固定代理 IP，不频繁切换
- 启动前验证代理连通性
- 定期检查 profile 目录是否保留登录状态

### 坑点2：Profile 预热被 Windows 安全策略拦截

**问题现象：**
- LinkedIn profile 预热任务无法执行
- CDP (Chrome DevTools Protocol) 检测未执行
- 自动化脚本静默失败

**根因分析：**
Windows 安全策略（如 Windows Defender、SmartScreen 或组策略）拦截了自动化浏览器的 CDP 连接，导致预热流程被阻断。

**解决方案：**
1. 调整浏览器安全设置，降低自动化检测敏感度
2. 使用更隐蔽的自动化方案（如 stealth 插件）
3. 在 VPS 上配置适当的安全策略例外

**预防措施：**
- 部署前先测试 CDP 连接是否被拦截
- 准备备选自动化方案
- 定期检查 Windows 安全策略更新是否影响自动化流程

### 坑点3：Telegram App 登录卡点

**问题现象：**
- Telegram App 无法完成登录
- 卡在 api_id/api_hash 验证环节
- 登录流程无限等待或报错

**根因分析：**
Telegram App 登录需要正确的 api_id 和 api_hash。这些参数获取和配置流程复杂，容易出错或被 Telegram 服务端拒绝。

**解决方案：**
**走 ADB 方式绕过 api_id/api_hash 卡点。**

具体步骤：
1. 不通过 Telegram API 登录
2. 使用 ADB 直接操作 GeeLark 云手机上的 Telegram App
3. 通过 UI 自动化完成登录流程（手机号+验证码）

**预防措施：**
- 优先选择 ADB 方式而非 API 方式操作 Telegram
- 提前准备好手机号和接收验证码的能力
- 避免在 API 层面纠缠 api_id/api_hash 问题

### 坑点4：社媒回复权限混乱

**问题现象：**
- 不清楚哪些回复可以直接发送
- 可能误发需要确认的回复
- 回复权限边界模糊，存在风险

**根因分析：**
没有建立明确的回复权限分级制度，导致自主回复和需确认回复的边界不清。

**解决方案：**
建立明确的**回复自主权规则**：

| 回复类型 | 权限 | 示例 |
|----------|------|------|
| 群内普通回复/互动 | ✅ 自主发送 | TG群聊日常互动、社媒群回复 |
| 针对主人帖子的评论回复 | ⚠️ 需确认 | 客户评论了主人的帖子后的回复 |
| 针对主人私信的回复 | ⚠️ 需确认 | 客户 DM 主人后的回复 |

**预防措施：**
- 操作前明确当前回复属于哪个类别
- 有疑问时默认走确认流程
- 定期回顾和更新回复权限规则

### 坑点5：社媒操作通道混乱

**问题现象：**
- 使用了错误的操作通道（如扣子云电脑、agent-browser）
- 不同操作在不同通道间混用
- 导致操作失败或环境不一致

**根因分析：**
没有统一规定操作通道，导致在不同场景下使用了不合适的工具。

**解决方案：**
建立**操作通道铁律**：

```
唯一通道：VPS (192.236.171.76) + GeeLark US Reality ADB
```

**禁止使用的通道清单：**
- ❌ 扣子平台云手机
- ❌ 扣子云电脑
- ❌ agent-browser
- ❌ 扣子沙箱浏览器

**预防措施：**
- 每次操作前确认使用的是正确通道
- 在操作脚本/指令中硬编码通道信息
- 新任务启动时先验证通道可用性

---

### 坑点6：ADB 操作 setStatus 参数错误

**问题现象：**
- 设备状态设置不正确
- 云手机状态异常
- 后续操作基于错误状态执行

**根因分析：**
调用 ADB setStatus 时未设置 `open:true` 参数，导致设备状态未正确更新。

**解决方案：**
调用 setStatus 时**必须**设置参数：
```
setStatus(open: true)
```

**预防措施：**
- 将 `open:true` 作为 setStatus 调用的标准模板
- 操作后验证设备状态是否正确
- 封装 ADB 操作函数，内置正确参数

## 快速排障清单

遇到问题时按以下顺序排查：

1. **登录问题** → 检查代理是否稳定、profile 是否持久化
2. **自动化失败** → 检查 Windows 安全策略、CDP 连接状态
3. **Telegram 登录** → 放弃 API 方式，改用 ADB
4. **回复权限** → 查阅回复自主权规则表
5. **操作通道** → 确认只使用 VPS + GeeLark ADB
6. **设备状态** → 检查 setStatus 是否带 open:true
