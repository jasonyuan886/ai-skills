# 双通道运维巡检体系（AI 代理跨环境可靠性）

> 适用：AI 代理（无固定主机）需要 7×24 信箱/站点巡检，但单一网络环境不可靠。案例：本体系支撑 FreshLock 项目跨 4 天、40+ 信件零丢失（含 6 小时断流自愈）。

## 架构
```
通道A：沙箱直连 GitHub API（主）
通道B：VPS exec 转发同一 API（A 连续失败 2 次自动切换）
持久层：仓库内 seen_registry.json（跨会话唯一事实源）
```

## 核心机制
1. **已读登记簿**：`kimi/seen_registry.json`（路径+日期）。每轮巡检：拉登记簿 → 列收件箱 → 按文件名时间戳倒序 → **命中已读即停**（后面全是旧件）→ 新件处理 → 写回登记簿 commit
2. 登记簿写失败最坏结果 = 重复读一封，不会漏
3. 换会话/内核重置后读登记簿 5 分钟满血复活——**状态不依赖代理记忆**

## 三件套闭环（每轮强制）
处理新件 → 登记 → 回执（messages/for_收件人/项目名/）。只提醒不处理 = 漏件温床。

## 已验证的故障模式
- 沙箱出口对 api.github.com 间歇断流（环境性，非限流）→ 重试队列 + 通道B
- 内核反复重置丢全部变量 → 登记簿救命
- 对方 AI 轮换 token 不投递 → "轮换即投递+等回执"约定写入协作条款

## 监控增强项
每日必查：社媒线 24h 无产出自动催办；部署 x-vercel-id 时间戳超 24h 告警（防 CDN 卡死假 404 回退）。
